The app writes full detail directly to a user-selected CSV while retaining only compact Rep + Action summary counts in memory.

Original count: one unique Create audit per table + record ID
Rep normalization: trims whitespace, collapses spaces, and combines names case-insensitively
Correction updates: Update audits made by Anslee Laroche or Matt Bleakley are applied to rep attribution
No double counting: Update events correct the Create record; they are not counted as additional uploads
Action: original cr714_action from Create is preserved; an authorized Update action is used only when Create action is blank
Memory model: source rows and correction rows are staged in IndexedDB one table at a time; detail CSV streams directly to disk
